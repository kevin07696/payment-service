### Business Logic Files
**Files:** `ACH_BUSINESS_LOGIC.md`, `CREDIT_CARD_BUSINESS_LOGIC.md`

### Integration Guide
**File:** `INTEGRATION_GUIDE.md`
**Decision:** ⚠️ **REFACTOR - make it reference other docs instead of duplicating**

**Current Issues:**
- Duplicates ADMIN_CLI.md (merchant registration)
- Duplicates BROWSER_POST_REFERENCE.md (browser post flow)
- Duplicates REACT_INTEGRATION.md (code examples)
- Duplicates AUTH.md (authentication)

Transform into a high-level "Getting Started" guide that:
1. Provides overview and prerequisites
2. **REFERENCES** detailed guides (not duplicating)
3. Shows decision tree: "Which integration method?"

## Auto-Generated Docs Strategy

### Question: How should generated docs work?

**Option A: Separate Files**
- `DATABASE_SCHEMA.md` - Auto-generated (gitignored)
- `DATABASE.md` - Hand-written design docs
- Pro: Clear separation
- Con: Users need to check both files

**Option B: Combined File**
- `DATABASE.md` - Generated file that includes:
  - Hand-written header/overview section
  - Auto-generated schema from migrations
  - Hand-written design decisions section
- Pro: Single source of truth
- Con: Generator more complex

**Option C: Generator with Template**
- Generator reads `DATABASE_TEMPLATE.md` for hand-written sections
- Merges with auto-generated content
- Outputs `DATABASE.md` (gitignored)
- Pro: Best of both worlds
- Con: Most complex to implement

**User preference?** Let's discuss which approach works best.
